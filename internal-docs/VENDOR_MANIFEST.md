### Why it is not yet referenced by any page

The live site requests `dist/umd/supabase.min.js` from jsDelivr with a floating
`@2`. Two things cannot be established from this environment:

1. `cdn.jsdelivr.net` is unreachable here (HTTP 403), so what production
   currently serves cannot be observed.
2. The npm package does **not contain** `dist/umd/supabase.min.js` — only
   `dist/umd/supabase.js`. The `.min.js` is generated by jsDelivr on the fly.
   The vendored file is therefore the same code but not the same bytes as what
   the browser receives today.

A floating `@2` also has no single answer over time: it resolves to whatever the
highest 2.x is at the moment of each request, and jsDelivr caches per edge.

2.116.0 is what `@2` resolves to today via the same npm registry jsDelivr reads
(dist-tag `latest`, highest of 248 published 2.x releases). That is strong
evidence but not proof of what production visitors are running.

Per the Group 5 instruction "if exact current production resolution cannot be
proven: STOP and report before selecting a version", this is staged and awaiting
confirmation.
